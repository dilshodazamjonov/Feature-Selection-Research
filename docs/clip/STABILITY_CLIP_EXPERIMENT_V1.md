# Stability CLIP experiment v1

## Objective and scope

This experiment completes the corrected CLIP comparison on Home Credit – Credit Risk Model Stability 2024. It implements exactly three feature-representation directions:

1. Stability-trained -> Stability
2. HomeCredit-trained -> Stability
3. LendingClub-trained -> Stability

It does not transfer a row-level credit classifier and it is not zero-shot default prediction. The source supplies a feature representation, source-fitted descriptor preprocessing, projection checkpoints, and an anchor. Stability supplies 1,959 frozen engineered feature identities, frozen semantic embeddings, and frozen target-free raw descriptors. Each resulting feature ranking is followed by Stability-supervised legacy mRMR and a Stability-trained LR or CatBoost classifier. ROC-AUC therefore belongs to the downstream classifier, not CLIP.

The implementation is isolated under `outputs/prompt_16_homecredit_model_stability_2024/clip_experiment_v1` and `results/prompt_16_homecredit_model_stability_2024/clip_experiment_v1`. Existing locked Stability, HomeCredit, and LendingClub results are read-only and are never regenerated or overwritten.

## Prompt-1 and target-free boundary

The orchestrator fails unless the Prompt-1 package validation is `PASS`, its SHA-256 inventory authenticates, and its universe is exactly 1,959 unique modeling variables. `target`, `date_decision`, and `case_id` cannot be predictor identities. Prompt-1 artifacts are never silently rebuilt.

The representation boundary permits only:

- `feature_text_v1`, generated by frozen `sentence-transformers/all-MiniLM-L6-v2` revision `main`, dimension 384, L2 normalized;
- `compact_target_free_v2`, dimension 13, in the frozen descriptor order;
- `identity_equivalence_v2` exact-identity exclusions and the frozen group-aware train/validation split;
- the frozen 23-member source anchor.

Target values, OOT values or labels, downstream outcomes, model outputs, classical-selector ranks, and LLM ranks are forbidden in CLIP training and ranking. Prompt-1 descriptors summarize target-free DEV feature distributions, so the CLIP representation is frozen across downstream row folds rather than recomputed inside every fold.

## Source-specific descriptor preprocessing

Stability-native training uses Prompt-1’s preprocessor exactly as fitted on representation-TRAIN feature identities: the first seven continuous descriptors receive `(value - median) / IQR` and clipping to `[-8, 8]`; the six indicators are unchanged. Validation feature identities, target, and OOT were excluded from fit.

HomeCredit transfer authenticates and uses the corrected HomeCredit median/IQR preprocessor, five corrected checkpoints, and the corrected consensus source anchor. LendingClub transfer authenticates and uses its different all-13-field median-imputation/standard-scaling preprocessor, five corrected checkpoints, and five seed-specific corrected source anchors. Both source preprocessors expose transform-only facades. Source projectors are frozen. No historical object has a training fallback and no object can be refit on Stability.

All historical paths are explicit in the frozen config. The resolver does not scan directories. It authenticates corrected-generation provenance, source dataset, `identity_equivalence_v2`, seeds, checkpoint and manifest hashes, the exact 384/13 -> 64/16 -> 32 architecture, 27,488 parameters, text identity, descriptor schema, preprocessor, and anchors.

## Stability representation training

Five independent CPU-deterministic projection heads are trained with seeds 11, 22, 33, 44, and 55. The architecture is the active `SemanticStatisticalContrastiveEncoder`: each view uses Linear -> GELU -> Dropout(0.05) -> Linear -> L2 normalization. Temperature is fixed at 0.07 with the locked `[0.02, 0.5]` clamp.

The objective is the corrected symmetric identity-pair contrastive loss:

```text
logits = T @ S.T / temperature
loss = 0.5 * (CrossEntropy(logits, identity) + CrossEntropy(logits.T, identity))
```

AdamW uses learning rate 0.001, weight decay 0.01, batch size 64, an 80-epoch cap, batches smaller than two skipped, and gradient clipping at 1.0. There is no scheduler. Early stopping uses source validation loss with patience 15 and minimum improvement 0.0001. The minimum source validation-loss checkpoint is selected independently for every seed. MRR and Recall@1/5/10 are diagnostics and never choose a checkpoint.

Seed directories preserve the best checkpoint and hash, checkpoint manifest, epoch history, best/stop epoch, validation loss, retrieval diagnostics, config/input identities, and a `COMPLETE` marker. Interrupted seed directories are archived within the isolated output tree. A completed seed is reused only after config, input, and checkpoint hashes authenticate.

## Consensus, anchors, and rankings

For each required seed, the semantic and statistical projections are averaged and L2-normalized. Seed 11 is the predeclared reference. Seeds 22, 33, 44, and 55 are aligned to seed 11 by deterministic orthogonal Procrustes, then all five matrices are averaged and L2-normalized. The builder rejects missing seeds, changed identity/order, any dimension other than 32, and NaN/Inf.

Stability-native ranking generalizes the corrected HomeCredit consensus method: the frozen Prompt-1 anchor member identities are located in consensus space, their centroid is normalized, and each feature receives cosine similarity. HomeCredit transfer uses the authenticated corrected HomeCredit consensus anchor against the aligned consensus. LendingClub preserves its materially different corrected reverse-transfer rule: each seed representation is scored against that seed’s authenticated source anchor and the five similarities are averaged. Its Procrustes consensus is retained as representation evidence, but does not replace the corrected ranking score.

Each direction produces one deterministic ranking of all 1,959 identities. Ties use descending CLIP score then ascending feature name. Ranking files record the source/target identity, universe hash, consensus method, source anchor identity, and source preprocessor identity.

## Downstream selection and temporal diagnostics

There are exactly six cells: three directions crossed with LR and CatBoost. LR takes the frozen CLIP top 60 and selects K=20. CatBoost takes the frozen top 100 and selects K=40. Pool sizes are never swept.

The authenticated `RandomForestRelevanceMRMRSelector` is used, not mutual-information mRMR. It applies 128-tree random-forest impurity relevance and greedy relevance divided by mean absolute Pearson-correlation redundancy, floored at 0.05. CLIP and mRMR operate on original engineered variables before model encoding. `OriginalFeatureNumericEncoder` supplies one numeric value per original candidate solely for selector fitting.

For each of the five locked expanding temporal folds, candidate data are restricted to exactly 60 or 100 columns before mRMR. The selector sees fold-TRAIN values and target only. `SparsePreprocessor` is then fitted on the final fold-TRAIN K only, followed by the fixed classifier on fold TRAIN only. Validation target is evaluation-only. OOF files retain `case_id`, `date_decision`, fold ID, target, prediction, direction, classifier, and stable experiment ID; the orchestrator verifies each locked validation identity occurs once and no OOT date is present.

The fixed Stability model preprocessor uses training-only numeric mean imputation with fallback zero, StandardScaler, categorical `Missing` fill, one-hot encoding with unknown-ignore and minimum frequency 10, and float32 CSR output. LR uses the locked liblinear configuration. CatBoost receives the encoded CSR representation and the fixed 1,500-iteration configuration with no eval set and no held-out early stopping.

DEV reporting includes the mean fold ROC-AUC, sample SD, pooled OOF ROC-AUC, consecutive-fold selected-feature Jaccard, elapsed time, and available process resource observations. These are diagnostics and cannot remove or tune a cell.

## Full-DEV freeze and OOT gate

For every cell, the same frozen candidate pool is applied to full DEV. Legacy mRMR, the model preprocessor, classifier, and KS threshold are fitted only on full DEV. The threshold uses full-DEV training predictions. All six fitted preprocessors/models and scientific choices are persisted before any OOT feature value can be opened.

`manifests/pre_oot_freeze_manifest.json` hashes the Prompt-1 package and universe, three rankings, candidate pools, fold selection evidence, full-DEV selected features, authenticated HC/LC source identities, Stability checkpoints, consensus manifests, model/preprocessor configuration, and random seeds. `StabilityMatrixAccess.load_oot` requires a gate token and re-authenticates the config, gate manifest, and every frozen file hash. A missing or mismatched gate denies access.

After the gate passes, OOT is final scoring only. There is no retraining, selector rerun, pool or K change, checkpoint/seed/ranking change, feature replacement, hyperparameter tuning, or OOT threshold tuning. All 304,916 locked OOT rows must survive with unique stable IDs. The final six-row result table reports OOT ROC-AUC, Gini, KS, lift/capture, threshold metrics, log loss, Brier score, score PSI against the frozen full-DEV prediction reference, and available resource observations alongside DEV diagnostics. The report says “higher observed OOT AUC” when comparison wording is needed and makes no automatic superiority or statistical-significance claim.

The terminal and `logs/run.log` show ten numbered stages, five seed starts/ends, throttled CLIP batches, epoch metrics, new-best and early-stop events, downstream folds, long-operation heartbeats, matrix parts, CatBoost, and OOT prediction batches. `logs/progress.jsonl` records timestamp, stage, direction, seed, epoch, batch, fold, event, metrics, and elapsed seconds.

Major stages and per-seed work use `COMPLETE` manifests with config, input, and output hashes. Matching complete work is reusable. A hash or configuration mismatch fails closed; interrupted work is not accepted as complete. The final integrity chain links repository commit, config, Prompt-1, historical sources, Stability checkpoints, rankings, selected features, predictions, metrics, report, and the SHA-256 inventory.
